# 2026-07-02 PostgreSQL News Digest

## Commits

Today saw a total of 15 commits, primarily focusing on maintenance and compatibility updates, alongside two notable new features. Highlights include enabling logical replication conflict logging to a dedicated table and the introduction of a new system view for statistics kind information. Several commits also address the long-standing policy of bumping minimum supported versions for client tools to v10.

---

### ⭐ [Allow logical replication conflicts to be logged to a table.](https://github.com/postgres/postgres/commit/a5918fddf10d297c70f7ec9067e9177e0be6d520)
**Amit Kapila**

This commit introduces a `conflict_log_destination` option for `CREATE` and `ALTER SUBSCRIPTION`, allowing logical replication conflicts to be recorded in an internal `pg_conflict_log_<subid>` table in addition to or instead of the server log. Previously, conflicts were only written as plain text to the server log, making them difficult to query or integrate with monitoring tools.

### ⭐ [Add system view pg_stat_kind_info](https://github.com/postgres/postgres/commit/3b066de6c0a1dadbd8bed107e55cae659af0598f)
**Michael Paquier**

This commit adds the `pg_stat_kind_info` system view, which exposes SQL-level metadata about statistics kinds registered within a PostgreSQL backend, including properties and the number of entries if tracking is enabled. This view provides detailed information about both built-in and custom statistics kinds, similar to `pg_get_loaded_modules()` for custom stats.
