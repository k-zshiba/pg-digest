### ⭐ [JSON_TABLE PLAN clause](https://github.com/postgres/postgres/commit/86ab7f4c721d61282c058acc0b4aa0b3adf04410)
**Author: Alexander Korotkov**

This patch adds the `PLAN` clauses for `JSON_TABLE`, allowing users to specify how data from nested paths are joined, providing considerable freedom in shaping the tabular output. `PLAN DEFAULT` offers a simpler way to define global strategies for sibling or child nested paths.

**Why it matters:** This feature significantly enhances the flexibility and control over how `JSON_TABLE` processes and transforms complex JSON data into relational tables, enabling more precise query optimization and data extraction from JSON structures.

### ⭐ [Add an enable_groupagg GUC parameter](https://github.com/postgres/postgres/commit/e01b23b84e4346c1941e2aad78e3d80a5498038d)
**Author: Richard Guo**

This commit introduces the `enable_groupagg` GUC, which provides a way to disable grouping that relies on presorted input, similar to `enable_hashagg`. It covers `GroupAggregate`, `Group` nodes, sort-based `Unique` steps, and the sorted mode of `SetOp`.

**Why it matters:** This GUC parameter offers database administrators and developers finer-grained control over the query planner's choices for aggregation strategies. It can be crucial for debugging cost misestimates or optimizing queries when a sorted grouping plan is unexpectedly chosen over a potentially cheaper hashed one.
