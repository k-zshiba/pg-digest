## Commits

Today's commits address critical stability and data integrity issues, particularly around logical decoding and the recently introduced graph database features.

### ⭐ [Record dependencies on graph labels and properties](https://github.com/postgres/postgres/commit/9d8cdcbe0c8aee743e29079bdb2e4b5eeae4c70e)
**Author: Peter Eisentraut**

This commit fixes a bug where views defined using `GRAPH_TABLE` did not properly record dependencies on referenced graph labels and properties. Previously, dropping a label or property used by such a view could lead to cache lookup errors when the view was accessed.

---

### [Fix race when logical decoding activation is concurrently interrupted.](https://github.com/postgres/postgres/commit/93a3e6839bf8d2e0498291335191b57ddf458b48)
**Author: Masahiko Sawada**

This patch resolves a race condition that could occur if logical decoding activation was concurrently interrupted by another backend. The previous cleanup callback logic could make unsafe assumptions about the state, potentially leading to issues.

---

### [Disallow direct use of the pgrepack logical decoding plugin](https://github.com/postgres/postgres/commit/cd7b204b2df99516a48a738e662d8512e706b519)
**Author: Álvaro Herrera**

This commit prevents the direct, standalone use of the `pgrepack` logical decoding plugin, as it is only intended for internal use during `REPACK (CONCURRENTLY)` operations. Attempting to use it directly now results in a clean error message, avoiding assertion failures or crashes.
